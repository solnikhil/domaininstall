# Milestone 4 — product-validation kit

M4 is **product validation**, not feature work. The CLI and release engineering
are far enough along that the binding constraint is whether anyone outside this
repository will publish a mapping, set one up without help, place it in their
docs, and understand the narrow security claim.

This kit supports a **quiet beta**: recruitment, unassisted DNS setup, placement
snippets, and measurement instruments. External human recruitment is required to
pass the gates; the materials here make that process measurable and repeatable.
None of the human gates are marked passed until real contacts convert and the
scorecard is filled in.

**Roadmap:** [ROADMAP.md §7](../../ROADMAP.md#7-milestone-4--product-validation)
— gates, thresholds, and the continue-vs-pivot decision rule.

## How to use the kit

1. **Recruit** with [OUTREACH.md](./OUTREACH.md); log every contact in
   [CONTACT-TRACKER.md](./CONTACT-TRACKER.md).
2. **Onboard** publishers with [PUBLISHER-GUIDE.md](./PUBLISHER-GUIDE.md) only —
   do not edit their DNS for them if you want gate 2 to count.
3. **Offer placement** copy from [PLACEMENT-SNIPPETS.md](./PLACEMENT-SNIPPETS.md).
4. **Run measurement** per [DISCOVERY-PROTOCOL.md](./DISCOVERY-PROTOCOL.md),
   [USAGE-DIARY.md](./USAGE-DIARY.md), and [COMPREHENSION.md](./COMPREHENSION.md).
5. **Operate** the two-week window with [RUNBOOK.md](./RUNBOOK.md).
6. **Score** outcomes in [RESULTS.md](./RESULTS.md) and apply the decision rule
   in [ROADMAP.md §7](../../ROADMAP.md#7-milestone-4--product-validation).

Do not invent contacts, inflate mapping counts, or mark a gate passed without
evidence that meets the threshold in the roadmap.
